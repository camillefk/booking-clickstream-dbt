# Data Modeling - Clickstream Dimensional Model

## 1. Overview

This document defines the **dimensional data model** (Star Schema) for the clickstream analytics platform.

### Why This Model?

- **Simple queries** - Analysts don't need complex joins
- **Fast performance** - Denormalized fact tables
- **Business-aligned** - Dimensions match business concepts
- **Easy to understand** - Non-technical stakeholders can follow

### Design Principles

1. **Separate concerns**: Facts (WHAT happened) vs Dimensions (CONTEXT)
2. **Denormalize for speed**: Acceptable redundancy for query performance
3. **SDC Type 1** Overwrite dimension history (simple, suitable for portfolio)
4. **Additive facts**: All metrics should be additive (sum across dimensions)

## 2. FACT TABLES 

### 2.1 fct_clickstream_events

**Purpose:** Track every user click/interaction with granular detail  

**Grain:** One row per event  

**Volume Estimate:** 1-10M rows (depends on traffic)  

**Materialization:** Table (performance)  


#### Schema

| Column Name | Data Type | Nullable | Description | Notes |
|---|---|---|---|---|
| **event_id** | STRING | ✕ No | Unique event identifier | PK; UUID generated |
| **user_id** | INTEGER | ✕ No | User who clicked | FK → dim_users |
| **session_id** | STRING | ✕ No | Session identifier | FK → fct_user_sessions |
| **page_id** | INTEGER | ✕ No | Page where event occurred | FK → dim_pages |
| **product_id** | INTEGER | ✓ Yes | Product involved (null if not applicable) | FK → dim_products |
| **date_id** | INTEGER | ✕ No | Date of event (YYYYMMDD format) | FK → dim_date |
| **event_timestamp** | TIMESTAMP | ✕ No | Exact time of event | UTC timezone |
| **event_type** | STRING | ✕ No | Type of event | Enum: 'pageview', 'click', 'purchase', 'add_to_cart' |
| **event_value** | FLOAT64 | ✓ Yes | Optional value (e.g., amount if purchase) | NULL for non-purchase events |
| **user_agent** | STRING | ✓ Yes | Browser/device info | For device/browser analysis |
| **referrer_url** | STRING | ✓ Yes | Where user came from | Null if direct |
| **loaded_at** | TIMESTAMP | ✕ No | When record was loaded to DW | Audit column |

#### Example Rows

| **event_id** | **user_id** | **session_id** | **page_id** | **product_id** | **date_id** | **event_timestamp** | **event_type** | **event_value** |
|----|----|----|----|----|----|----|----|----|
| evt_001 | 123 | s_123_001 | 456 | NULL | 20260511 | 2026-05-11 10:30:45 | pageview | NULL |
| evt_002 | 123 | s_123_001 | 789 | 999 | 20260511 | 2026-05-11 10:32:13 | click | NULL |
| evt_003 | 123 | s_123_001 | 789 | 999 | 20260511 | 2026-05-11 10:35:46 | purchase | 150.00 |

#### Key Insights (for analytics)

- **Additive metrics**: event_value can be SUM'd (total revenue)
- **Dimensional analysis**: Group by event_type, page_id, user_id
- **Time-based**: Can analyze by date, hour, day of week
- **User behavior**: Track funnel (pageview → click → purchase)

### 2.2 fct_user_sessions

**Purpose:** Aggregated user sessions (key for understandind behavior)  

**Grain**: One row per user session  

**Volume Estimate**: 100K-1M rows  

**Materialization:** Table (performance)  


**Why this table?**
- Analysts want to answer: "What's the average session duration?"
- Without this, they'd need complex ``GROUP BY`` with window functions
- Pre-calculating saves time and reduces errors

#### Schema 

| Column Name | Data Type | Nullable | Description | Notes |
|---|---|---|---|---|
| **session_id** | STRING | ✕ No | Unique session identifier | PK; Generated by sessionization logic |
| **user_id** | INTEGER | ✕ No | User in session | FK → dim_users |
| **session_start_ts** | TIMESTAMP | ✕ No | Session start time | UTC |
| **session_end_ts** | TIMESTAMP | ✕ No | Session end time | UTC |
| **session_duration_minutes** | FLOAT64 | ✕ No | Duration in minutes | = (end - start) / 60 |
| **session_start_date_id** | INTEGER | ✕ No | Date session started (YYYYMMDD) | FK → dim_date |
| **session_end_date_id** | INTEGER | ✕ No | Date session ended (YYYYMMDD) | FK → dim_date (may differ if session crosses midnight) |
| **pages_visited** | INTEGER | ✕ No | Count of unique pages in session | Integer count |
| **total_events** | INTEGER | ✕ No | Count of all events in session | Includes pageviews, clicks, etc |
| **purchases_in_session** | INTEGER | ✕ No | Count of purchase events | 0 if no purchases |
| **revenue_in_session** | FLOAT64 | ✕ No | Total $ spent in session | Sum of purchase values |
| **entry_page_id** | INTEGER | ✓ Yes | First page visited | FK → dim_pages |
| **exit_page_id** | INTEGER | ✓ Yes | Last page visited | FK → dim_pages |
| **has_purchase_flag** | INTEGER | ✕ No | Did session result in purchase? | 0 or 1 (for filtering) |
| **loaded_at** | TIMESTAMP | ✕ No | When record was loaded | Audit column |

#### Example Rows

| **session_id** | **user_id** | **session_start_ts** | **session_end_ts** | **duration_min** | **pages_visited** | **purchases** | **revenue** |
|----|----|----|----|----|----|----|----|
| s_123_001 | 123 | 2026-05-11 10:30 | 2026-05-11 10:47 | 17.0 | 3 | 1 | 150.50 |
| s_124_001 | 124 | 2026-05-11 11:45 | 2026-05-11 11:53 | 8.0 | 8 | 2 | 300.50 |
| s_123_002 | 123 | 2026-05-11 11:50 | 2026-05-11 11:55  | 5.0 | 2 | 0 | 0.00 |

#### Key Insights

- **Conversion analysis**: has_purchase_flag = 1 → purchased users
- **Session quality**: pages_visited, duration, revenue per session
- **Repeat users**: same user_id, multiple session_ids
- **Time patterns**: session_start_ts analysis (peak hours)

### 2.3 fct_purchases

**Purpose:** Completed purchase transactions  

**Grain:** One row per purchase event  

**Volume Estimate:** 10K-100K rows  

**Materialization:** Table (performance)  


**Why separate table?**
- Purchases are **most important** metric (revenue!)
- Needs special handling (SCD2 for refunds? approval workflows?)
- Often queried separately for BI/FinOps

#### Schema

| Column Name | Data Type | Nullable | Description | Notes |
|---|---|---|---|---|
| **purchase_id** | STRING | ✕ No | Unique purchase transaction ID | PK; UUID |
| **user_id** | INTEGER | ✕ No | User who purchased | FK → dim_users |
| **session_id** | STRING | ✕ No | Session where purchase occurred | FK → fct_user_sessions |
| **product_id** | INTEGER | ✕ No | Product purchased | FK → dim_products |
| **date_id** | INTEGER | ✕ No | Date of purchase (YYYYMMDD) | FK → dim_date |
| **purchase_timestamp** | TIMESTAMP | ✕ No | Exact purchase time | UTC |
| **quantity** | INTEGER | ✕ No | Number of items | 1+ |
| **unit_price** | FLOAT64 | ✕ No | Price per item | At time of purchase |
| **total_amount** | FLOAT64 | ✕ No | quantity × unit_price | Revenue metric |
| **discount_amount** | FLOAT64 | ✓ Yes | Discount applied | NULL if no discount |
| **final_amount** | FLOAT64 | ✕ No | total_amount - discount_amount | What customer actually paid |
| **payment_method** | STRING | ✓ Yes | How paid (credit_card, paypal, etc) | For payment analysis |
| **purchase_status** | STRING | ✕ No | Status of purchase | Enum: 'completed', 'pending', 'refunded' |
| **loaded_at** | TIMESTAMP | ✕ No | When record loaded | Audit column |

#### Example Rows 

| **purchase_id** | **user_id** | **product_id** | **date_id** | **quantity** | **final_amount** | **purchase_status** |
|----|----|----|----|----|----|----|
| pur_001 | 123 | 999 | 20260511 | 1 | 150.00 | completed |
| pur_002 | 124 | 1000 | 20260511 | 2 | 89.98 | completed |
| pur_003 | 125 | 999 | 20260511  | 1 | 135.00 | completed |

#### Key Insights

- **Revenue tracking**: SUM(final_amount) by dimension
- **Product analysis**: Which products sell most?
- **Customer value**: Revenue per user_id
- **Discount impact**: How much discount affects revenue?

## 3. DIMENSION TABLES

### 3.1 dim_users

**Purpose:** User master data (WHO is clicking?)  

**Grain:** One row per user  

**Volume Estimate:** 1K-100K rows  

**Materialization:** Table (performance)  

**Type:** Slowly Changing Dimension Type 1 (SCD1)
- We **overwrite** user data (no history)
- Simpler for portfolio, suitable for user attributes tha don't need history  

#### Schema 

| Column Name | Data Type | Nullable | Description | Notes |
|---|---|---|---|---|
| **user_id** | INTEGER | ✕ No | Unique user identifier | PK; From raw events |
| **user_name** | STRING | ✓ Yes | User display name | May be anonymous |
| **email** | STRING | ✓ Yes | User email | For contact/personalization |
| **signup_date** | DATE | ✓ Yes | When user registered | For cohort analysis |
| **country** | STRING | ✓ Yes | User country (from IP) | For geographic analysis |
| **device_type** | STRING | ✓ Yes | Typical device (mobile, desktop, tablet) | Most common device used |
| **preferred_language** | STRING | ✓ Yes | User language preference | For localization analysis |
| **is_active_flag** | INTEGER | ✕ No | Is user currently active? | 0 or 1 |
| **last_active_date** | DATE | ✓ Yes | Last time user clicked | For churn analysis |
| **lifetime_sessions** | INTEGER | ✕ No | Total sessions ever | Aggregate metric |
| **lifetime_purchases** | INTEGER | ✕ No | Total purchases ever | Aggregate metric |
| **lifetime_revenue** | FLOAT64 | ✕ No | Total $ spent | VIP scoring |
| **loaded_at** | TIMESTAMP | ✕ No | When record loaded | Audit |
| **_dbt_valid_from** | TIMESTAMP | ✓ Yes | SCD1 validity start | NULL (not using SCD2) |
| **_dbt_valid_to** | TIMESTAMP | ✓ Yes | SCD1 validity end | NULL (not using SCD2) |

#### Example Rows

| **user_id** | **user_name** | **signup_date** | **country** | **is_active_flag** | **last_active_date** | **lifetime_revenue** |
|----|----|----|----|----|----|----|
| 123 | Cami Focke | 2026-01-15 | DE | 1 | 2026-05-13 | 550.00 |
| 124 | Jane Smith | 2026-01-27 | NL | 1 | 2026-05-12 | 300.50 |
| 125 | Bob Wilson | 2026-02-10 | NL | 0 | 2026-03-07 | 50.00 |

#### Key Insights

- **User segmentation**: By country, device, signup cohort  
- **VIP analysis**: lifetime_revenue > threshold
- **Churn detection:** is_active_flag = 0 AND last_active_date < 30 days ago 
- **User quality**: lifetime_sessions, lifetime_purchases

### 3.2 dim_pages

**Purpose:** Website pages catalog (WHERE did users click?)  

**Grain:** One row per unique page  

**Volume Estimate:** 50-500 rows  

**Materialization:** Table (fast lookups)  

**Type:** SCD1 (pages rarely change fundamentally)  


#### Schema

| Column Name | Data Type | Nullable | Description | Notes |
|---|---|---|---|---|
| **page_id** | INTEGER | ✕ No | Unique page identifier | PK; Derived from URL |
| **page_name** | STRING | ✕ No | Human-readable page name | e.g., "Hotel Details" |
| **page_url** | STRING | ✓ Yes | Full URL path | For debugging/linking |
| **page_category** | STRING | ✕ No | Page type/category | Enum: 'search', 'details', 'checkout', 'confirmation', 'homepage' |
| **page_type** | STRING | ✓ Yes | Technical type | 'static', 'dynamic', 'checkout' |
| **is_conversion_page_flag** | INTEGER | ✕ No | Does this page lead to purchases? | 1 if checkout/confirmation, 0 otherwise |
| **is_exit_page_flag** | INTEGER | ✕ No | Users exit from here? | 1 if high exit rate, 0 if transitional |
| **page_created_date** | DATE | ✓ Yes | When page was created | For product analytics |
| **page_last_modified_date** | DATE | ✓ Yes | Last significant change | For versioning |
| **loaded_at** | TIMESTAMP | ✕ No | When loaded | Audit |

#### Example Rows

| page_id |	page_name |	page_category |	is_conversion_page |	page_url |
|----|----|----|----|----|
|456 |	Hotel Details |	details |	0 |	/hotels/456 |
|789 |	Booking Form |	checkout |	1 |	/booking/form |
|111 |	Search Results |	search |	0 |	/search?city=* |
|222 |	Confirmation |	confirmation |	1 |	/confirmation |

#### Key Insights

- **Funnel analysis**: Track flow search → details → checkout → confirmation
- **Page performance**: Which pages have highest click-through rate?
- **Exit rate**: Where users abandon?

### 3.4 dim_date

**Grain:** One row per calendar day  

**Volume Estimate:** ~1000 rows (covers ~2.7 years)  

**Materialization:** Table  

**Note:** This is a **reference/master dimension** - dates are critical for ANY analytics  


#### Schema

| Column Name | Data Type | Nullable | Description | Notes |
|---|---|---|---|---|

| **year** | INTEGER | ✕ No | Year | 2026 |
| **quarter** | INTEGER | ✕ No | Quarter | 1-4 |
